**Part A: Replace HighStopwatch kernel32.dll P/Invoke**

Read `Assets/Scripts/Assist/HighStopwatch.cs`. It uses `[DllImport("kernel32.dll")]` for `QueryPerformanceCounter` and `QueryPerformanceFrequency` -- Windows-only APIs that will fail on Linux.

Replace the entire implementation with `System.Diagnostics.Stopwatch`:
- Remove all `[DllImport("kernel32.dll")]` declarations
- Remove `QueryPerformanceCounter` and `QueryPerformanceFrequency` extern methods
- Replace with `System.Diagnostics.Stopwatch` which is cross-platform and provides the same high-resolution timing
- Maintain the same public API surface (method names and return types) so callers don't need changes
- Add `using System.Diagnostics;` if not already present

**Part B: Replace WWW class usage**

Research found 3 occurrences in 2 files. Find them:
```bash
grep -rn "new WWW\|WWW(" Assets/ --include="*.cs"
```

Replace `WWW` with `UnityWebRequest`:
- `new WWW(url)` becomes `UnityWebRequest.Get(url)` with `SendWebRequest()` and `downloadHandler.text`
- `yield return www` becomes `yield return request.SendWebRequest()`
- `www.text` becomes `request.downloadHandler.text`
- `www.bytes` becomes `request.downloadHandler.data`
- `www.error` becomes `request.error` (check `request.result != UnityWebRequest.Result.Success`)
- Add `using UnityEngine.Networking;` to affected files
- The WWW -> UnityWebRequest migration changes the pattern from constructor-starts-download to explicit SendWebRequest(), so coroutine flow may need adjustment

**CAUTION:** These files may also reference proprietary plugins (NGUI, uLink). Only replace WWW usage -- do NOT try to fix other compilation errors in the same files. Those are Phase 2 scope.
  </action>
