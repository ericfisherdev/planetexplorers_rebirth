<objective>
Implement WASD player movement with terrain collision so the player can walk, run, sprint, and jump on the generated terrain.

Purpose: Movement is the primary player interaction. Without it, the player is a static capsule. The original codebase routes input through PeInput -> MainPlayerCmpt.UpdateMoveState() -> Motion_Move_Human -> HumanPhyCtrl -> PEMotorPhysics. This chain has many dependencies (SkillSystem, animation, IK). We create a clean movement controller that reads Unity input directly and moves the player via CharacterController (simpler collision than Rigidbody for character movement).

Output: Player moves with WASD, sprints with Shift, jumps with Space. Gravity pulls player to terrain. Collisions prevent walking through solid objects.
</objective>

  <action>
    Create a clean movement system that replicates the original game's movement feel without the deep dependency chain.

    1. **Create `Assets/Scripts/Rebirth/Player/RebPlayerInput.cs`:**
       - MonoBehaviour `RebPlayerInput` in namespace `Pathea.Rebirth`
       - Public read-only properties:
         - `Vector3 MoveInput` -- raw WASD/arrow input as (horizontal, 0, vertical), magnitude clamped to 1
         - `bool JumpPressed` -- true on the frame Space is pressed (GetKeyDown)
         - `bool SprintHeld` -- true while Left Shift is held (GetKey)
         - `bool WalkToggle` -- toggled by pressing CapsLock or a configurable key
       - In `Update()`:
         - Read `Input.GetAxisRaw("Horizontal")` and `Input.GetAxisRaw("Vertical")`
         - Compose into `MoveInput = new Vector3(h, 0, v).normalized` (only normalize if magnitude > 1, to preserve analog stick deadzone if using gamepad)
         - Read `JumpPressed = Input.GetKeyDown(KeyCode.Space)`
         - Read `SprintHeld = Input.GetKey(KeyCode.LeftShift)`
         - Toggle walk mode on key press
       - No dependency on PeInput -- this is a clean replacement. PeInput can be wired back in later when the full input system is restored.

    2. **Create `Assets/Scripts/Rebirth/Player/RebPlayerMotor.cs`:**
       - MonoBehaviour `RebPlayerMotor` in namespace `Pathea.Rebirth`
       - Requires `CharacterController` component (use `[RequireComponent(typeof(CharacterController))]`)
       - Public fields matching original speeds:
         - `float walkSpeed = 2f`
         - `float runSpeed = 5f`
         - `float sprintSpeed = 8f`
         - `float jumpHeight = 1.5f`
         - `float gravity = 20f` (original uses 10 but CharacterController needs higher for good feel)
         - `float groundCheckDistance = 0.1f`
       - Private state:
         - `CharacterController controller`
         - `RebPlayerInput input`
         - `Vector3 velocity` (tracks vertical velocity for gravity/jump)
         - `bool isGrounded`
       - In `Awake()`:
         - Get `CharacterController` component. Configure: height=1.8, radius=0.3, center=(0, 0.9, 0), slopeLimit=45, stepOffset=0.3
         - Get `RebPlayerInput` component (require it on same or parent GameObject)
       - In `Update()`:
         - **Ground check:** Use `controller.isGrounded`. When grounded, reset vertical velocity to a small downward value (-2f) to keep grounded state stable.
         - **Movement direction:** Convert input.MoveInput from local space to world space relative to the player's current facing direction OR the camera's forward direction. Use `Camera.main.transform` if available:
           ```
           Transform cam = Camera.main?.transform;
           Vector3 forward = cam != null ? Vector3.ProjectOnPlane(cam.forward, Vector3.up).normalized : transform.forward;
           Vector3 right = cam != null ? Vector3.ProjectOnPlane(cam.right, Vector3.up).normalized : transform.right;
           Vector3 moveDir = forward * input.MoveInput.z + right * input.MoveInput.x;
           ```
         - **Speed selection:** If input.SprintHeld -> sprintSpeed, else if input.WalkToggle -> walkSpeed, else runSpeed
         - **Apply horizontal movement:** `controller.Move(moveDir * currentSpeed * Time.deltaTime + Vector3.up * velocity.y * Time.deltaTime)`
         - **Jump:** If input.JumpPressed AND isGrounded: `velocity.y = Mathf.Sqrt(jumpHeight * 2f * gravity)`
         - **Gravity:** `velocity.y -= gravity * Time.deltaTime`
         - **Face movement direction:** If moveDir magnitude > 0.1, smoothly rotate transform.forward toward moveDir using `Quaternion.Slerp` with a rotation speed of ~10f
       - Public method `void Teleport(Vector3 position)` -- disable controller, set transform.position, re-enable controller. This is needed because CharacterController blocks direct position changes.

    IMPORTANT: Use `CharacterController` instead of `Rigidbody` for the player. CharacterController provides built-in ground detection, slope limits, and step-over that would require complex raycasting with Rigidbody. The original game uses Rigidbody (PEMotorPhysics) but has hundreds of lines of custom ground detection code that we're not ready to replicate.

    IMPORTANT: The RebGameStarter from Plan 01 needs to be updated to add these components to the player. Add a note in RebPlayerMotor that it should be added to the player GameObject alongside RebPlayerInput. If Plan 01 used a Rigidbody, the motor's Awake should remove the Rigidbody (CharacterController and Rigidbody conflict). Log a warning if both are found.
