<objective>
Bootstrap the player entity creation pipeline so that entering play mode spawns a player entity at a valid world position with a visible representation.

Purpose: This is the foundation for all player interaction -- without a spawned entity, movement and camera have nothing to attach to. The original codebase bootstraps through a complex PeLauncher chain with many singleton dependencies. We create a simplified bootstrap path that creates the player entity directly, bypassing the full launcher queue while still using the real EntityMgr and PeEntity systems.

Output: A playable scene where entering Play mode creates a player entity (with capsule placeholder mesh) at a hardcoded valid terrain position, registered in EntityMgr and accessible via MainPlayer.Instance.entity.
</objective>

  <action>
    The original bootstrap chain (GlobalBehaviour -> PeGameMgr -> PeLauncher -> LoadCreature) has many singleton dependencies that may not be initialized yet. Create a simplified bootstrap that directly creates the player entity using the same underlying systems but with fewer prerequisites.

    1. **Create `Assets/Scripts/Rebirth/Bootstrap/RebPlayerBootstrap.cs`:**
       - Static class `RebPlayerBootstrap` with method `SpawnPlayer(Vector3 spawnPos)`
       - The method must:
         a. Ensure EntityMgr singleton exists (check Instance, create if needed)
         b. Ensure WorldInfoMgr singleton exists for ID generation
         c. Call `MainPlayer.Instance.CreatePlayer(WorldInfoMgr.Instance.FetchRecordAutoId(), spawnPos, Quaternion.identity, Vector3.one, null)`
         d. If MainPlayer/PeEntityCreator chain fails (likely due to missing singletons), fall back to creating the player entity directly:
            - Create a new GameObject("Player")
            - Add PeEntity component
            - Add PeTrans component
            - Add a CapsuleCollider (height=1.8, radius=0.3, center=(0, 0.9, 0))
            - Add a Rigidbody (freeze rotation, no gravity initially for testing)
            - Add a MeshFilter + MeshRenderer with a primitive capsule mesh for visibility
            - Set position to spawnPos
            - Log the creation method used (original chain vs fallback)
         e. Return the created PeEntity (or null on complete failure)
       - IMPORTANT: Wrap the original-chain attempt in try/catch. The fallback ensures we always get a player even if the full entity system isn't ready yet.
       - Use namespace `Pathea.Rebirth`

    2. **Create `Assets/Scripts/Rebirth/Bootstrap/RebGameStarter.cs`:**
       - MonoBehaviour `RebGameStarter` in namespace `Pathea.Rebirth`
       - Public field `Vector3 spawnPosition = new Vector3(7168f, 150f, 7168f)` (center of a typical PE map, elevated above terrain)
       - In `Start()`:
         a. Set `PeGameMgr` static fields for single player mode if accessible (try `PeGameMgr.playerType = EPlayerType.Single` or equivalent)
         b. Call `RebPlayerBootstrap.SpawnPlayer(spawnPosition)`
         c. Log success/failure
       - In `Update()`: If player entity exists but is falling through the world (position.y < -100), teleport back to spawnPosition and log a warning

    3. **Create `Assets/Resources/EntityPlayer.prefab`** (via script or describe for manual creation):
       - Since we cannot create prefabs via script outside the editor, document in a comment in RebGameStarter.cs that the EntityPlayer prefab needs to be created in the Unity Editor with these components:
         - PeEntity
         - PeTrans
         - MainPlayerCmpt
         - CapsuleCollider (height=1.8, radius=0.3)
         - Rigidbody (freezeRotation=true, useGravity=true)
         - A child MeshFilter+MeshRenderer with capsule mesh
       - The fallback path in RebPlayerBootstrap handles the case where this prefab doesn't exist yet.

    IMPORTANT: Do NOT try to fix or modify the original PeLauncher/PeGameMgr chain. The simplified bootstrap runs alongside it. The original chain can be restored later once all singletons are properly initialized.
  </action>
