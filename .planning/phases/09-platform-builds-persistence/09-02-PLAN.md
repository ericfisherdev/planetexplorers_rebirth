<objective>
Create a modern Unity 6 build pipeline script that produces standalone Linux x64 and Windows x64 builds, replacing the legacy BuildPlayer.cs which uses deprecated Unity 5 APIs.

Purpose: The original BuildPlayer.cs references deprecated BuildTarget enums (StandaloneLinux, StandaloneLinuxUniversal, StandaloneOSXIntel, StandaloneOSXIntel64), uses the old BuildPipeline.BuildPlayer overload that returns a string (Unity 6 returns BuildReport), references SVN and Steam/FMOD scripting defines, and targets Mac/32-bit builds we do not need. We need a clean build script that targets only Linux x64 and Windows x64 for the Rebirth project.

Output: A new Editor script under Assets/Editor/BuildPipeline/ with menu items to build Linux and Windows standalone executables.
</objective>

<!-- Unity 6 BuildPipeline API (key changes from Unity 5) -->

Unity 6 BuildPipeline changes vs Unity 5:
- BuildPipeline.BuildPlayer now returns BuildReport (not string)
- BuildTarget.StandaloneLinux removed (use StandaloneLinux64)
- BuildTarget.StandaloneLinuxUniversal removed (use StandaloneLinux64)
- BuildTarget.StandaloneOSXIntel removed (use StandaloneOSX)
- BuildTarget.StandaloneOSXIntel64 removed (use StandaloneOSX)
- EditorUserBuildSettings.SwitchActiveBuildTarget requires (BuildTargetGroup, BuildTarget) overload
- PlayerSettings.SetScriptingDefineSymbolsForGroup still works but SetScriptingDefineSymbols (with NamedBuildTarget) is preferred

From Assets/Scripts/AiScripts/Editor/BuildPlayer.cs:
```csharp
// Original uses: BuildTarget.StandaloneLinux, StandaloneLinuxUniversal, StandaloneOSXIntel, etc.
// Original uses: string error = BuildPipeline.BuildPlayer(...) -- string return is removed in Unity 6
// Original uses: PreBuild() calls SVN commands
// Original uses: "SteamVersion;FMOD_LIVEUPDATE" scripting defines
```
