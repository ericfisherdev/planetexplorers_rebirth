By Phase 6, all stubs exist (Phase 2), the project compiles cleanly (Phase 3), terrain renders (Phase 4), and player spawns with movement (Phase 5). The SkillSystem code references `Mono.Data.SqliteClient` for skill data loading from the database — this should already work since SQLite access is in the codebase. The attack flow is: Player triggers attack -> animation plays -> `PEAttackTrigger` activates collider -> collider overlaps `PEDefenceTrigger` on target -> `onHitTrigger` event fires -> damage routed to target's `SkEntity` -> `SkAttribs` HP decremented -> `PESkEntity` fires `onHpChange`/`deathEvent`.

2. **PEDefenceTrigger to SkEntity** — Read `PEDefenceTrigger.cs`. It should be attached to target entities and reference their `SkEntity`. When a hit is received:
   - Extract the attacker's `SkEntity` from the `PEAttackTrigger`'s `m_SkEntity` field
   - Extract the target's `SkEntity` from the `PEDefenceTrigger`
   - Call damage through the SkillSystem: either `target.SkEntity.ApplyDamage(attacker, damageAmount)` or trigger a damage skill

3. **PEHitDetector** — Read this file. It may be an alternative/simpler hit detection path. Ensure it also routes to the SkEntity damage pipeline.

5. **Layer mask verification** — `PEAttackTrigger.attackLayer` must include the layer that target entities are on. Check `Pathea.Layer` constants in the codebase. If layers are misconfigured, log a warning with the expected layer setup.

6. **Fallback direct damage** — If the full PEAttackTrigger->PEDefenceTrigger flow cannot work without animation events (which may not be set up on placeholder models), add a TEMPORARY direct damage path: when `PEAttackTrigger.active` is set true, do a `Physics.OverlapSphere` at the attack position and directly apply damage to any `PESkEntity` found within range. Add `Debug.Log` at: trigger activation, hit detection, damage routing.
