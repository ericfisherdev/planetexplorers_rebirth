Key context: The behavior tree system is custom-built (NOT the proprietary Behave plugin). The source is fully in the repo under `Assets/Scripts/BehaviorTree/Scripts/` and `Assets/Scripts/Behave/`. The proprietary `Behave.Runtime` namespace was used for types like `Tree`, `BLBlackboard`, `IAgent` — these were stubbed in Phase 2. However, the ACTUAL behavior tree implementation (`BTResolver`, `BTLauncher`, `BTAgent`, `BTAction`, `BTCoroutine`) is in the repo and is the runtime that matters.

The flow is: `BehaveCmpt.Excute()` -> `BTLauncher.Instance.Excute(behaveID)` -> `BTLauncher` ticks `BTAgent` each frame -> `BTAgent` runs its tree -> tree nodes dispatch to `BTAction` subclasses (loaded via reflection from XML) -> `BTNormal` (the base action class) accesses entity components.

Tree data is loaded from XML files via `BTResolver.Resolver(btPath)` which reads behavior tree XML from Resources. The XML defines tree structure and which `BTAction` classes to use.

`BTNormal.InitAgent()` grabs references to entity components: `m_Entity`, `m_SkEntity`, `m_Motor`, `m_Target`, `m_Animator`, etc. All of these should exist on entities by Phase 5.
</context>

Read ALL files in `Assets/Scripts/BehaviorTree/Scripts/` to understand the full behavior tree runtime.

1. **BTLauncher** — This is the central singleton that ticks all registered behavior trees. Read it fully. Verify:
   - It extends `Singleton<BTLauncher>` or `PESingleton<T>` and will be available at runtime
   - `Excute(int behaveID)` registers a tree for ticking
   - `Stop(int behaveID)` / `Reset(int behaveID)` / `Pause(int behaveID, bool)` work
   - The Update/tick loop iterates registered trees and calls `BTAgent.Tick()`

2. **BTResolver** — Loads behavior tree definitions from XML. Read it fully. Verify:

   - `RegisterToCache(string btPath)` and `ApplyCacheBt()` pre-load trees

3. **BTAgent** — The per-entity behavior tree instance. Verify:
   - `Tick()` traverses the tree and dispatches to `BTAction` subclasses
   - `Clone()` creates independent copies (needed because `Pop` returns clones)
   - The tree traversal respects `BehaveResult.Running` (continue), `Success`, `Failure`

4. **BTAction** — Abstract base for all tree node actions. Verify:
   - `InitAgent(IAgent)` is called when the tree is assigned to an entity
   - `Tick(Tree sender)` is the main execution method
   - The reflection-based action loading (via `[BehaveAction]` attribute) works. Check `Reflecter.cs` for how actions are discovered.

5. **BTCoroutine** — The tree uses coroutines for async behavior. Verify it works with Unity 6's coroutine system.

6. **Behave.Runtime stubs** — The repo code uses `Behave.Runtime.Tree`, `BehaveResult`, `IAgent`, `BehaveAction` attribute. These are defined in the BehaviorTree code itself (NOT in the proprietary plugin). Verify that the Phase 2 stubs don't CONFLICT with these in-repo definitions. If there are duplicate type definitions (stub vs repo), remove the stubs for types that are already defined in repo code. The in-repo definitions in `BTInterface.cs` should take precedence.
