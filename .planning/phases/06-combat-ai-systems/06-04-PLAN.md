Key context: The AI combat loop has several interconnected systems:

1. **Spawning**: `SPPoint` creates creature entities at world positions. `SPGroup` manages groups of spawn points. Entity creation goes through `EntityMgr` or direct prefab instantiation.

2. **Target Detection**: `TargetCmpt` uses `PEVision` and `PEHearing` sensors to detect nearby entities. It maintains a hatred list (`m_Enemies` = `List<Enemy>`). The `Enemy` class (defined at bottom of TargetCmpt.cs) tracks hatred value, distance, and validity.

3. **AI Controller**: `AiObject` (partial class across AiController.cs, AiAttack.cs, AiBehave.cs, etc.) is the main AI MonoBehaviour. It extends `SkillRunner` (which provides skill execution). `AiBehave` connects to the behavior tree system.

4. **Combat BT Actions**: `BTAttack.cs` contains `BTCalculateAttackMode` (selects attack pattern), `IAttack`/`IAttackPositive`/`IAttackRanged` interfaces. `BtNpcCombat.cs` has NPC-specific combat behaviors.

5. **Pathfinding**: `AiSeeker` wraps A* Pathfinding `Seeker` component. By Phase 2, this is stubbed. The stub's `Seeker` should provide basic pathfinding or at minimum not crash. If pathfinding is fully stubbed (no-op), creatures can still move directly toward targets using `Vector3.MoveTowards` — less realistic but functional.
</context>
