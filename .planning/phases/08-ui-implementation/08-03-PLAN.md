Purpose: The HUD is the player's primary information display during gameplay. Without it, players cannot see their health, navigate, or access quick items (UI-02).

Output: Four HUD components (health/stamina bars, minimap, hotbar) rendering as a uGUI overlay during gameplay.
</objective>

    Create `Assets/Scripts/UI/HUD/` directory.

    **HUDController.cs:** MonoBehaviour singleton managing the in-game HUD.
    - On Awake: create Canvas (Screen Space - Overlay, sort order 50), add CanvasScaler (Scale With Screen Size, 1920x1080 reference).
    - `m_PlayerEntity` reference -- attempt to get from `PeCreature.Instance.mainPlayer` on Start. If null, retry each frame in Update until available (player may spawn after HUD).
    - `Show()` / `Hide()` methods to toggle HUD visibility.
    - Create child GameObjects for each HUD section:
      1. Top-left anchor: HealthStaminaBar
      2. Top-right anchor: MinimapDisplay
      3. Bottom-center anchor: HotbarDisplay
    - In `Update()`: if player entity is available, push attribute values to child components.
    - Get HP from player's PESkEntity component: `entity.GetCmpt<PESkEntity>()` then read current/max HP. If PESkEntity or its methods are stubs, use fallback test values (75/100 HP, 80/100 stamina).
    - Expose public `SetTestValues(float hp, float stamina)` for testing without live entity.

    **HealthStaminaBar.cs:** MonoBehaviour for the health/stamina bar group.
    - Create two horizontal bars programmatically:
      1. Health bar: 250x20 pixels, positioned top-left (30px from edges). Background Image (dark red rgba(0.3,0,0,1)), foreground filled Image (red rgba(0.8,0.1,0.1,1)). Label showing "HP: {current}/{max}" via TextMeshProUGUI.
      2. Stamina bar: 250x16 pixels, below health bar (8px gap). Background (dark green), foreground filled (green rgba(0.1,0.7,0.2,1)). Label "STA: {current}/{max}".
    - `SetHealth(float current, float max)` -- updates fill amount (current/max clamped 0-1) and label text.
    - `SetStamina(float current, float max)` -- same pattern.
    - Use Image.fillMethod = Horizontal, Image.fillOrigin = Left.
    - Smooth fill changes via Mathf.Lerp in Update (lerp speed 5f) for visual feedback.

    Follow codebase conventions: PascalCase methods, m_ field prefix, singleton pattern.

  <action>
    **MinimapDisplay.cs:** MonoBehaviour for the minimap in top-right corner.
    - Create a 200x200 pixel container anchored to top-right (30px from edges).
    - Background: dark bordered panel (Image with dark background, 2px border).
    - Create a dedicated minimap Camera as a child:
      - Orthographic, looking straight down (rotation 90,0,0)
      - Culling mask: terrain/environment layers only
      - RenderTexture: 256x256, depth 16
      - Orthographic size: 50 (shows ~100 unit radius around player)
    - Display the RenderTexture on a RawImage inside the container.
    - Player indicator: small arrow/dot Image centered on the minimap, rotated to match player's Y rotation.
    - In Update: move minimap camera to follow player position (x, y+100, z). If player entity not available, position at (0, 100, 0).
    - Time display: TextMeshProUGUI below minimap showing game time. Query `GameTime` if available, else show "Day 1 12:00".
    - Compass labels: N/S/E/W TextMeshProUGUI at edges of minimap circle.

    **HotbarDisplay.cs:** MonoBehaviour for the quick-access hotbar at bottom center.
    - Create a horizontal row of 8 item slots, centered at screen bottom (30px from bottom edge).
    - Each slot: 60x60 pixel Image (dark background with light border), inside a HorizontalLayoutGroup with 4px spacing.
    - Selected slot indicator: brighter border on the currently selected slot (default: slot 0).
    - Slot number labels: small TextMeshProUGUI in top-left corner of each slot ("1" through "8").
    - `SetSlotItem(int index, Sprite icon, int count)` -- sets the item icon and stack count for a slot. If icon is null, show empty slot.
    - `SetSelectedSlot(int index)` -- highlights the selected slot border.
    - In Update: check number key inputs (1-8) to change selected slot. Fire `onSlotSelected(int index)` event.
    - Integration point: attempt to read from `PackageCmpt` on player entity for item data. If unavailable, show empty slots (acceptable at this phase).

    Both components should degrade gracefully when game systems are stubs -- show placeholder/empty state rather than crashing.
