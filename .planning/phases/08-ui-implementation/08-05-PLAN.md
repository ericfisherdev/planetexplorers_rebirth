  <action>
    Create `Assets/Scripts/UI/Crafting/` directory.

    **CraftingScreenController.cs:** MonoBehaviour singleton managing the crafting screen.
    - Canvas: Screen Space - Overlay, sort order 200, initially inactive.
    - Toggle: In Update, check for KeyCode.C press to toggle Show/Hide. Close on Escape. Do NOT open if InventoryScreenController is already showing (check its isShow state).
    - Layout (built programmatically):
      1. Semi-transparent overlay (same as inventory)
      2. Crafting panel: 900x650 centered, dark background with border
      3. Title: "Crafting - Replicator" TextMeshProUGUI
      4. Left column (300px): RecipeListPanel
      5. Right column (560px): CraftingDetailPanel
      6. Bottom of right column: CraftingProgressBar
      7. Close button: "X" in top-right

    - Data binding on Show(): attempt to get `ReplicatorCmpt` from player entity. If available, query recipe list. If null (stubs), populate with 8 test recipes:
      - "Iron Sword" (requires: Iron Ingot x3, Wood x1)
      - "Wood Shield" (requires: Wood x5, Leather x2)
      - "Health Potion" (requires: Herb x2, Water x1)
      - "Iron Pickaxe" (requires: Iron Ingot x2, Wood x2)
      - "Leather Armor" (requires: Leather x4, Thread x2)
      - "Torch" (requires: Wood x1, Cloth x1)
      - "Iron Ingot" (requires: Iron Ore x2)
      - "Cooked Meat" (requires: Raw Meat x1)

    **RecipeListPanel.cs:** MonoBehaviour for the left recipe list.
    - Search bar: TMP_InputField at top, filters recipes by name substring on value change.
    - Category dropdown: simple row of toggle buttons (All, Weapons, Armor, Tools, Consumables, Materials). Filters recipe list by category.
    - Scrollable list: ScrollRect with VerticalLayoutGroup content. Each recipe entry is a 280x40 button with:
      - Recipe name (TextMeshProUGUI, left-aligned)
      - Small item icon (30x30 Image, right side)
      - Highlight on hover, selected state with accent border
    - On recipe click: notify CraftingScreenController, which updates CraftingDetailPanel.
    - `SetRecipes(List<RecipeData> recipes)` -- populates the list. RecipeData is a local struct: { string name, string category, List<MaterialRequirement> materials, string resultItemName, int resultCount, float craftTime, Sprite icon }.
    - `MaterialRequirement` struct: { string itemName, int required, int available, Sprite icon }.

    **CraftingDetailPanel.cs:** MonoBehaviour for the right detail area.
    - Result item display: large icon (80x80 Image) + name (TextMeshProUGUI, bold, size 24) + description (size 14).
    - Materials grid: VerticalLayoutGroup listing each required material:
      - Each row: material icon (40x40), material name, "X / Y" count where X = available in inventory (green if enough, red if not), Y = required.
    - Craft button: 200x50 button at bottom. Enabled only when all materials are available (all green). Disabled (grayed) when materials insufficient.
    - Quantity control: "-" button, count label (default "1"), "+" button to set craft quantity. Max capped by material availability.
    - `SetRecipe(RecipeData recipe)` -- populate all fields. Check material availability against PackageCmpt if available, else show test quantities (have 5 of each material for test recipes).
    - `OnCraftClicked()` -- start crafting operation: disable craft button, show progress bar, begin timer.

    **CraftingProgressBar.cs:** MonoBehaviour for crafting progress visualization.
    - Layout: 400x30 bar below the detail panel.
    - Background Image (dark), foreground filled Image (gold/yellow), percentage TextMeshProUGUI centered.
    - `StartCraft(float duration)` -- begin filling over duration seconds. Update fill in Update() using Time.deltaTime.
    - `OnCraftComplete` event -- fires when progress reaches 1.0. CraftingScreenController handles this by:
      1. Attempting to call ReplicatorCmpt.StartReplicate() if available
      2. Showing "Crafted: {itemName}!" confirmation text (fade out after 2 seconds)
      3. Updating material counts (deduct used, add result)
      4. Re-enabling craft button
    - `Cancel()` -- reset bar, re-enable button.
    - Visual: pulse effect on completion (brief scale tween on result icon).

    All game system calls guarded with null checks. Test data provides visual verification when systems are stubs.
